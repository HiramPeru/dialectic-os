2. Próximo Bloque Prioritario

P2 - Endurecer operación y observabilidad

Las prioridades P1 ya quedaron implementadas y verificadas localmente. La siguiente fase debe convertir el MVP en una operación más controlable: trazabilidad del pipeline completo y calibración de calidad para reducir falsos positivos.

  • Agregar vista expandida de errores y payload completo por job desde la UI operacional.
  • Separar extracción de claims como job independiente si se decide desacoplarla de ingesta.
  • Calibrar umbrales de retrieval y adjudicación contra una muestra revisada manualmente.
  • Agregar tests de integración con base de datos aislada.

Criterio de aceptación: un operador puede saber qué jobs corrieron, cuántos claims/artículos procesaron, qué errores hubo y qué contradicciones requieren acción.

4. Riesgos Técnicos a Cuidar

  • No reintroducir O(n²) con Gemma. Todo nuevo scan debe pasar por retrieval/candidatos.
  • No dejar fixtures en DB. Usar rollback o limpieza explícita.
  • No activar scanner automático por defecto. Puede disparar llamadas lentas a Ollama en desarrollo.
  • Cuidar Alembic. Toda columna/tabla nueva necesita migración reproducible.
  • No asumir que Ollama tiene modelo de embeddings en otros entornos. En esta máquina ya está nomic-embed-text, pero nuevos contenedores o hosts deben validarlo con ollama list.
  • No confiar en documentos ausentes. Si otro agente cita walkthrough.md, primero confirmar que el archivo exista en este repo.
